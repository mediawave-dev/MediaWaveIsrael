הכפתור הוא שורת סטטוס של פריסה. ריחוף מריץ תצוגה מקדימה בלי להתחיל, לחיצה שולחת, פס הבנייה מתמלא מימין לשמאל מאחורי הטקסט והופך אותו, והסוף נוחת כ"באוויר": נקודה שמתמלאת בתוך טבעת דיו.

הסיפור של לחיצה אחת. ריחוף מריץ את הפס מימין לשמאל בשני עצירות קצרות, כמו בנייה, העלאה והפצה (560ms). עזבתם באמצע? הפס לא חוזר אחורה: הוא ממשיך ויוצא שמאלה, כמו חבילה שיצאה לדרך (400ms).

לחיצה מורידה את הכפתור פיקסל אחד, מעבה את המסגרת ומשלימה את הפס (170ms). השחרור קופץ חזרה עם עודף קטן.

שליחה: התצוגה המקדימה יוצאת שמאלה (320ms), ומיד מתחילה ריצה אמיתית מאפס: מהירה, עוצרת, ממשיכה, ונזחלת לעבר 86% בלי להגיע לסוף. רק תשובת השרת מסיימת אותה. זה הפס הכי כן שיש: הוא לא מעמיד פנים שהוא יודע כמה נשאר.

נשלח: הקטע האחרון נוחת בהחלטיות (260ms), הנקודה מתמלאת בתוך הטבעת עם קפיצה קטנה, וטבעת אחת יוצאת ממנה פעם אחת ונעלמת. באוויר.

שגיאה: הפס מתגלגל אחורה בשישה פריימים (300ms, W10) והטבעת נשארת פתוחה. בלי רעד, בלי אדום. מרחפים עליה, והיא מציעה ריצה חדשה.

04איך זה נבנה על StateButton

מבנה אחד, תכונה אחת לכל שכבה: .dw__fill מחזיקה את הקצה המוביל (clip-path), .dw__run את הקצה הנגרר (clip-path), הכפתור עצמו את הלחיצה (transform). התווית מצוירת פעמיים, והעותק שבתוך הפס בצבע ההפוך, כך שאף אות לא מוסתרת באף פריים.

// src/look/buttons/DeployButton.tsx
export function DeployButton(props: LookButtonProps) {
  const ref = useRef<HTMLElement | null>(null)
  useDeployRun(ref, props.state ?? 'idle')       // ship -> reset -> creep, see below
  return (
    <StateButton {...props} cls="dw"
      onPoint={(el, p) => p ? runIn(el) : runOut(el)}   // fine pointers only (StateButton)
      render={(label, state) => (<>
        <span className="dw__label"><Glyph />{label}</span>
        <span className="dw__run" aria-hidden="true">
          <span className="dw__fill"><span className="dw__label"><Glyph />{label}</span></span>
        </span>
      </>)} />
  )
}
// Glyph = <svg viewBox="0 0 12 12"> ring (r 5) · gap ring (pathLength 100, dasharray 74 26)
//         · core (r 2.4, scale 0 -> 1 on sent) · ping (r 5, one 900ms ping on sent)

CSS states (deploy-button.css, all in this file's <style>):
  rest            fill inset(0 0 0 100%)   run inset(0)              no transition
  [data-run=in]   fill inset(0)  560ms linear() with two holds  (hover / :focus-visible)
  [data-run=out]  run  inset(0 100% 0 0)  400ms                 (leave: exits to the left)
  [data-pressed]  fill inset(0) 170ms; transform translateY(1px) scale(.985) 70ms; ::before rim opacity
  loading         fill inset(0 0 0 14%) 9s creep, no loop
  sent            fill inset(0) 260ms; core scale(1) +150ms; ping once +380ms
  error           fill inset(0 0 0 100%) steps(6) 300ms; ring -> open ring (opacity)
  reduced motion  transition-property: opacity only; loading = empty fill + dimmed ring

JS (three small pieces, one attribute write per event):
  1. runIn / runOut: write data-run="in" | "out"; 400ms after "out" remove it (both edges jump home
     while nothing is visible). Touch: pointerdown sets "in" (with data-pressed), pointerup "out".
     Blur keeps the run if the pointer is still over the button; leave keeps it if it has focus.
  2. useDeployRun(state): idle -> loading while the preview is showing:
     data-run="ship" (320ms) -> data-run="reset" -> force a reflow -> remove data-run, so the
     creep starts from zero. sent -> idle: data-run="out" (the full bar exits left).
  3. Hover on error is allowed (it is a retry): the error rule applies only without data-run.
No pointer position is needed: the run always reads right to left, wherever the cursor enters.

שמות הסטטוס שבכפתור באים כמו שהם מ-STATE_LABEL: "שולחים", "נשלח. נחזור אליכם היום", "לא נשלח. נסו שוב". לא נוסף אף טקסט חדש לתוך הכפתור. שורת היומן מתחת לטופס מציגה רק שעה אמיתית ואת אותן מילים.
